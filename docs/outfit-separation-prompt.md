- 版本：1.0
- 更新日期：2026-11-09
- 对应功能：[穿搭分离流程](outfit-separation-flow.md)
- 字段口径：[开发字段契约第 8 节](developer-field-contract.md#8-穿搭分离)
- 状态：用于后续真实模型接入的提示词草案，尚未经过真实模型效果验证。当前 HTML 仍使用固定示例，不调用模型；页面保存的简短生成要求用于交互演示，不代表本完整提示词已在后台部署。

## 1. 功能目标

用户上传一张单人模特穿搭图，点击「一键分离穿搭」，后台将原图与预设提示词交给支持图片输入的图像生成或编辑模型，输出**一张完整的白底穿搭平铺合集图**。

服装、鞋履、袜子、包袋及配饰放在同一张图中，呈现整套穿搭的商品平铺效果。最终不是逐件独立图片，也不包含模特、原背景、文字标签或多张拼接边框。

## 2. 输入与输出

| 项目 | 约定 |
| --- | --- |
| 必填输入 | 一张模特穿搭图片，作为商品内容的唯一依据 |
| 前端文件限制 | JPG/JPEG/PNG/WEBP，单张不超过 10 MB |
| 用户操作 | 上传或选择图片后直接提交，无需填写或确认提示词 |
| 提示词 | 后台固定配置，前端不开放编辑 |
| 结果数量 | 每次任务输出一张完整平铺合集图 |
| 背景与构图 | 白色背景、竖版构图、自然平铺、合理留白、不重叠 |
| 下载格式 | PNG；如模型返回其他格式，由后处理转为 PNG，不只修改文件后缀 |
| 商品关联 | 输入若来自库商品，结果保留稳定 productId；普通图片不推断商品归属 |

竖版比例遵循已确认的页面口径。具体比例和像素尺寸应在模型接入时按能力确定，当前页面未提供比例与清晰度选择，不在此新增已确认参数。

## 3. 可直接使用的完整提示词

采用「任务目标 + 原图约束 + 构图要求 + 输出格式」结构。将以下文本与用户上传的原图一同提交；原图必须作为实际图片输入，不能仅把文件名或路径写进文本。

```text
任务：将输入图片中模特身上的整套穿搭，转换为一张完整的白底商品平铺合集图。

【单品提取】
识别图中可明确看见、由该模特实际穿戴或携带的服装、鞋履、袜子、包袋及配饰。
将这些单品从人物与原背景中分离出来，去除人物的面部、头发、皮肤、手脚及身体轮廓。
只保留原图中存在且可以辨认的单品，不加入背景里的物品，不根据穿搭习惯增加原图没有出现的商品。
如果原图是半身或局部照片，只整理可明确辨认的单品，不补充画面外的下装、鞋袜或其他配饰。

【商品还原】
尽量保留各单品原有的颜色、款式、剪裁、材质纹理、图案、可辨认的品牌标识、纽扣、拉链、口袋与装饰细节。
不要重新设计商品，不要更换颜色、面料、图案或款式，不要凭空增加或改写品牌标识。
服装展开为自然、舒展的正面平铺状态，保留合理的立体感与轻微褶皱，去除人体穿着形成的明显身体轮廓。
对能够判断整体款式、仅有少量遮挡的单品，可按可见结构做最小必要补全；无法确认的细节保持简洁，不创造新的装饰结构。
鞋袜在原图能明确判断为一对时成对摆放；不要把一对拆成重复商品，也不要无依据地复制其他单品。

【同图排版】
所有单品必须出现在同一张竖版画布中，形成完整穿搭的平铺陈列。
根据实际单品数量与体积安排布局：服装作为主要视觉，鞋袜、包袋和配饰围绕服装自然分布；没有对应品类时自然调整布局，不预留固定空位。
各单品完整可见，互不重叠、互不遮挡，彼此留出适当间距。
保持合理的相对大小和均衡留白，不机械地把所有物品缩放到同样大小，不裁切边缘。
使用连续的白色背景与柔和、统一的光线，可有轻微自然接触阴影，呈现干净、清晰、真实的电商商品平铺摄影效果。
不要给每件商品添加独立卡片、分格线、边框或色块，不要表现为多张照片拼接。

【输出要求】
仅输出一张完整的白底穿搭平铺合集图。
画面中不出现人物、人体残留、模特、人体模架、衣架、原场景或无关道具。
不增加标题、品类标签、说明文字、水印、尺寸标注或装饰性排版。
商品原本可辨认的印花文字与品牌标识属于商品本身，应尽量保留，不视为新增文字。
只输出最终图片，不输出分析过程、文字解释、单品清单或多个备选结果。
```

## 4. 可选负向约束

仅在所接模型支持独立负向提示词字段时单独传入；不支持时，主提示词已经包含相应约束，不需要虚构接口参数。

```text
人物，面部，头发，皮肤，人体残留，手脚，人体模架，衣架，原背景，无关道具，新增商品，重复单品，商品重叠，遮挡，裁切，不完整商品，款式改动，颜色偏移，图案改变，虚构品牌标识，新增标题，品类标签，说明文字，水印，分格线，边框，多张拼图，插画风，卡通风
```

不得将「所有文字、所有标识」一概排除，以免破坏商品自身印花或品牌图样。

## 5. 后台调用与归档建议

1. 校验文件类型、大小和图片可读性；输入无效时保留用户已有素材，返回可理解的错误。
2. 创建 taskId，固定本次输入图片与可选 productId，读取 `outfit_flatlay_v1` 对应完整提示词。
3. 将原图作为图像输入，与主提示词一起传入模型。模型若支持独立结果数量或尺寸参数，按一张、竖版配置；提示词文本不能替代接口参数。
4. 结果生成后检查是否为一张可读的图片，再进行预览与 PNG 下载处理。输出不符合要求时标记失败或进入受控重试，不用固定示例冒充真实结果。
5. 成功后创建一个 assetId：source=穿搭分离、assetType=image，关联 taskId 及可选 productId。结果进入 AI生成；有商品关联时同时展示在该商品详情。
6. 历史保存本次实际使用的完整提示词快照、提示词标识与版本、模型及参数、输入图片引用、商品信息快照、结果与资产 ID，便于追溯。

真实服务建议增加 `promptId`、`promptVersion`、`resolvedPrompt` 字段，具体接口字段名在接入时确定；当前静态原型尚未实现这些后台字段。更新后台提示词不能覆盖旧历史中已经保存的实际提示词。

## 6. 效果验收与限制

| 检查项 | 通过标准 |
| --- | --- |
| 输出形式 | 一张完整图片，所有单品同图平铺；无独立卡片或分隔边框 |
| 内容依据 | 仅包含原图可辨认的穿戴单品，不加入搭配建议商品 |
| 商品一致性 | 可见颜色、款式、纹理与图案尽量一致，无明显结构变形 |
| 背景与人物 | 白色背景，无原场景与人体残留 |
| 排版 | 各件完整、不重叠、不裁切，留白均衡 |
| 文字 | 无新增标签或水印；商品自身可见印花文字尽量保留 |
| 历史与归档 | 每任务一个合集资产，提示词与版本可追溯，商品关联正确 |

建议用全身穿搭、半身穿搭、单件连体装、外套叠穿、带鞋袜包饰和明显遮挡的照片分别验证。原图没有鞋包时，结果不应自行添加；同一商品不应重复出现。

生成模型可能重绘或补全部分结构，提示词不能保证像素级一致，严重遮挡下也无法恢复未知的真实细节。这份提示词需结合实际模型试跑调整；当前没有真实效果评测结论。

## 7. 后续同类需求的交付约定

凡通过「用户素材 + 后台固定提示词」实现的图片或视频功能，需同时交付 `docs/<功能名>-prompt.md`，包含完整可复制提示词、输入输出要求、必要的负向约束、后台参数与提示词的分工、版本、验收标准及演示边界。

提示词应与对应流程说明和字段契约相互链接。新增或调整输出规则时同步更新提示词文档，不能只写「由 AI 自动生成」或仅描述效果。
