# 账户中心：积分、订单与多团队成员管理

版本 v1.3，2026-11-13。原型 [account-center.html](../account-center.html?tab=credits)；统一口径见[开发字段契约](developer-field-contract.md)，菜单总览见[个人菜单文档](personal-menu-flow.md)，充值与套餐见[价格体系](pricing-system.md)。设计已由用户确认。所有账户数据为当前浏览器本地演示，不连接账号、支付、邮件或真实积分服务。

## 1. 页面与入口

保留全站216px主侧栏。内容区左侧仅三个页签：积分明细、订单明细、成员管理；顶部空间选择框与创建团队按钮。宽度900px以下次级页签转为横排，表格仅在自身容器横滚，不撑宽页面。

- 路由：account-center.html?tab=credits|orders|members&workspace=<稳定ID>。无参数默认积分明细及本机当前空间；无效页签回积分，空间不存在提示错误，不展示其他空间的账目。点击页签支持浏览器前进/后退，刷新保持目标空间和页签。
- 头像菜单新增「积分明细」，「充值记录」更名「订单明细」，直达对应页签；「邀请有礼」进入当前空间积分明细并预筛选邀请奖励。
- 「当前团队」行右侧显示「切换」，点击整行直接进入当前空间成员管理页，不再展开菜单内的二级列表。通过账户中心顶部空间选择框切换个人/团队及创建团队，切换同步底部空间名、菜单积分及页面数据。
- 仅积分明细页显示「充值 / 升级」，打开原三Tab弹窗；成员管理和订单明细不显示此按钮；咨询和选择积分包仍不创建真实订单或到账流水。

## 2. 本地数据、余额与隔离

共享 account-store.js；localStorage 单键 fashmaker-account-center-v1，结构 {version:1,currentWorkspaceId,workspaces,ledger,orders}。每次写入先读取最新数据、校验、完整写回，成功才发布 fashmaker-account-changed 事件。跨页通过storage同步；浏览器多标签并发不具备服务端事务或CAS保障。存储异常提示并保留表单，不宣称成功。

首次建立个人账户、内容工作室、品牌运营组三个示例空间：personal / team-studio / team-brand。个人为自定义模型版；示例和新建团队明确「团队版 · 演示」，不产生购买、不改变个人/自定义模型不含团队管理的套餐规则。示例个人包含5条流水，余额420；示例团队各5条，余额3820。额度、邀请奖励和注册赠送均为演示样例，不是套餐或邀请活动的正式定价。新团队余额0，无订单，只有创建者。

隔离仅限新增账目与成员模块。现有商品库、资产、创作历史、模型配置不因本次切换实现真实团队权限隔离。默认当前账号为 user-ricky / Ricky Tang / ricky@example.com，不复制参考图私人账号或邮箱。示例林小夏为 lin@example.com。

## 3. 积分明细

| 列 | 定义 |
| --- | --- |
| 流水号 | 稳定id，可打开详情 |
| 标题 | 本次业务说明；退款同时显示原流水号 |
| 成员 | 发生时成员姓名及账号快照，不按邮箱或同名合并 |
| 变动类型 | consume消费 / refund退款 / recharge充值 / gift赠送 / invite_reward邀请奖励 / transfer_out派送支出 / transfer_in派送收入 |
| 变动积分 | 有符号整数；扣减红色负数，收入绿色正数，不仅依赖颜色 |
| 剩余积分 | 当前空间按时间升序累计到该笔的余额；列表倒序，筛选不重算历史余额 |
| 变动时间 | at毫秒时间戳，按Asia/Shanghai展示 |

ledger每条还含workspaceId、memberId、memberName、memberEmail、demo=true；退款有relatedId引用原消费，充值可有orderId。原消费不删除或再抵消，退款单独正流水。邀请好友奖励以正数invite_reward进入同一列表，与邀请团队成员区别，不因发出邀请自动奖励。

顶部余额=全部delta之和；累计获得=正数且非退款之和；累计净消费=max(0,-sum(消费+退款))。成员累计用量按当前团队memberId汇总同一消费/退款规则。不对参考截图的已退款消费行再做第二次抵消。

筛选：流水号/标题trim后大小写不敏感包含匹配、类型、成员、开始/结束日期，取交集；日期按上海时区包含全天。类型/成员默认all，日期默认空。筛选只影响列表，汇总保持全空间。页大小5/10/20/50，默认20；改变条件回第一页，无结果明确空态；只显示当前空间记录。

## 4. 订单明细

顶部显示当前空间套餐、余额；下方为订单号、商品/套餐、类型、周期、支付金额、状态、下单时间、支付时间、操作人、详情。订单类型membership会员/credits积分包；状态pending待支付、paid已支付、closed已关闭、refunded已退款；金额以amountCents整数分存储，展示两位小数元。未支付时间null展示暂无。

每条订单保留workspaceId、memberId/name、baseCredits、bonusCredits及demo=true。只读详情展示空间、状态、时间、积分与演示说明。可按订单号/商品搜索、类型及状态筛选，分页同积分页。示例团队各1条已支付新手积分包，关联同空间3800充值流水；个人及新团队无订单。未确认的会员赠送值不伪造数字。

本次没有创建/支付/退款订单的操作。现有购买咨询与积分包选择不改变订单数、余额或会员。

## 5. 多团队

团队名称trim后必填1–50字符，本机已存在的团队不可同名。ID通过crypto.randomUUID建立，不靠名称关联。创建后切换到该团队成员页，创建者为所有者；可以继续创建其他团队，不增加真实会员订阅。

个人空间成员页提示无需成员管理，提供创建/切换团队入口。团队切换不删除原空间数据。当前原型支持个人向团队派送积分，不提供团队删除、所有权转移、团队向个人退回或团队之间转账。

## 6. 成员与邀请

列：成员（用户名+邮箱）、备注、角色、状态、加入时间、累计用量、额度上限、最后登录、操作。可按用户名/邮箱搜索和状态筛选；默认在册=active+invited，removed/canceled可通过筛选回看。

| 字段 | 规则 |
| --- | --- |
| email | trim小写，必填有效邮箱≤254字符，同团队active/invited不能重复；跨团队可分别邀请同邮箱 |
| note | trim，选填≤100字符 |
| role | admin管理员 / member成员，默认member；owner由创建团队产生，不可邀请/降级 |
| quota | 空=null不限，否则非负安全整数；0允许。仅记录演示额度，不对现有生成服务实施真实限额 |
| status | invited待加入 / active已加入 / canceled已取消 / removed已移除 |
| joinedAt / lastLoginAt | 时间戳或null；未加入/未登录展示暂无，模拟加入不伪造真实登录 |
| token | 仅待加入邀请存在的本地随机标识，接受/取消后删除；不是线上可鉴权凭证 |

创建邀请只新增该团队invited记录，不发送邮件或通知。可查看/复制演示邀请链接，复制失败保留可手动选择的链接。待加入可编辑备注/角色/额度、取消或显式模拟接受；接受后转active并记加入时间，不自动增加积分。链接为account-center.html?tab=members&workspace=<id>&invite=<token>，只在含该本地记录的同一浏览器可用；已取消/接受则提示失效。链接页仍要求显式模拟接受，不自动加入。

成员编辑不可改邮箱；移除保留成员ID及原流水归属，状态转removed；邀请取消转canceled。所有者行无移除/降级按钮，store同样拦截。当前账号在团队内必须为active owner/admin才能管理；所有示例团队及新团队中当前账号均为创建者。仅本地权限校验，不代表线上账号鉴权。

团队表单打开时锁定目标空间；跨页切换空间后提交原表单提示重新操作，避免邀请到错误团队。关闭/Esc不保存未提交字段，重新打开重置；存储失败保留表单并显示原因。

## 7. 验收与边界

1. 菜单显示积分明细/订单明细，旧充值记录文案消失；三个次级页签可切换、刷新、前进后退。
2. 消费、退款、充值、赠送、邀请奖励同表展示；示例个人余额420、团队3820；退款不重复抵扣；成员列与筛选存在。
3. 可创建至少两个新团队，稳定ID不同，积分与订单空态正确；相同邮箱可分别邀请，数据不串空间。
4. 邀请默认待加入，支持编辑、复制链接、取消、模拟接受；无邮件请求；取消/接受后旧token不可再次使用；所有者保护有效。
5. 移除成员不删历史，成员用量与退款一致；备注100、团队名50、邮箱及额度负数/小数校验有效。
6. 订单筛选、详情可用；打开充值及点击积分包不会新增paid订单或改变余额。
7. 关键词、日期、类型、成员交集和分页正确；筛选不改余额，空态明确，刷新与跨标签同步当前空间。
8. 桌面与390px页面无横向溢出；表格自身滚动，Tab及表单有标签，Esc/外部点击关闭弹窗并恢复焦点。

没有真实账号、支付、邀请邮件、活动奖励、额度执行或原有创作任务扣费。本地示例流水不与每次生成自动联动。本次不改变图片/视频生成提示词或产物归档规则，因此无需新增prompt文档。

## 8. 个人向团队派送积分（v1.1，2026-11-13）

仅积分明细标题区显示「派送积分」「派送记录」，不新增第四个左侧页签。积分类型增加派送收入、派送支出，另有「派送记录（收入/支出）」组合筛选。

派送弹窗展示来源账号Ricky Tang的个人账户及当前可用余额，接收团队下拉、当前团队积分、派送积分、备注。团队页面默认该团队，个人页默认第一个可管理团队；只能选择当前账号为active owner/admin的团队。积分必填正安全整数且不得大于个人余额，备注trim后≤200字符。提交锁定打开表单时的当前空间；跨页切换后须重新打开，避免派错。取消/关闭/Esc不改余额，失败保留输入并反馈。

确认时在同一个localStorage状态中一次写入两条流水：个人transfer_out=-amount，团队transfer_in=+amount；同一transferId、来源/目标ID与名称快照、操作人、时间、备注，linkedLedgerId相互关联。每条依旧有自己的唯一流水id，均demo=true。更新后个人余额减少、目标团队增加，总积分守恒；不创建付款订单，不作为消费或退款，不改变成员quota或累计消费。以本次请求的transferId防重复；相同ID相同内容重复提交不再次扣减，内容不一致报错。提交前重新读最新余额并校验；写入失败两边都不落账。

派送记录弹窗仅展示当前空间的派送单号、来源账号、接收团队、带符号变动积分、操作成员、派送时间和备注；个人查看派出，目标团队查看收到，其他团队不显示该笔。完整流水详情补充派送单号、来源、接收团队、对方流水号和备注。旧数据无需迁移，首次无记录明确空态，不伪造历史派送。

余额与菜单同步仍基于同一ledger；累计获得包含transfer_in，净消费仅consume/refund。当前派送是本机模拟，不是真实平台积分划转；不新增真实支付或邮件。正式服务须用服务端账本事务、幂等、权限和积分批次校验，不可把浏览器多标签顺序写入视为分布式事务。

新增验收：个人420派送100后个人320、目标团队3820→3920，另一个团队3820不变；两边同单号一正一负，总额不变；筛选和记录均能看；刷新保留；重复请求只一对；余额不足/0/负数/小数/不可管理目标拒绝且无流水；模拟存储失败无单边记账；成员用量及订单数量不变。
