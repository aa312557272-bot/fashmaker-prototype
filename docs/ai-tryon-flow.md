# FashMaker AI 换装 · 功能与开发说明

> 版本：2026-11-06。交付范围：已确认交互、字段约定与开发验收。  
> 对应本地原型：`ai-tryon.html`，包含「换装 / 改姿势 / 多模特 / 多商品」四个页签。当前网页尚未同步发布到 GitHub Pages。  
> 精确字段枚举与默认值见 [developer-field-contract.md 第 7 节](developer-field-contract.md#7-ai-换装)。当前原型使用浏览器存储与演示图片，不代表真实 AI 服务或线上持久化已经接入。

## 1. 目标与范围

面向服饰电商运营，通过服装与人物参考图，完成换装、姿势扩展，以及按模特或按商品分别生成展示图。

| 页签 | 商品 / 服装 | 人物 / 模特 | 输出规则 |
| --- | --- | --- | --- |
| 换装 | 统一上传 1–6 张服装参考图；不区分套装、多件或上下装上传入口 | 单个模特 | 按选择输出 1–4 张 |
| 改姿势 | 不要求商品图，保留人物原服装 | 单张人物图；预设姿势或自定义参考 1–8 个 | 每个姿势 1 张 |
| 多模特 | **商品单选**，1 个库商品或 1 张商品图 | **模特多选**，合计 1–8 个 | 每个模特 1 张 |
| 多商品 | **商品多选**，1–5 项，每项 1 张商品图 | **模特单选**，1 个 | 每个商品 1 张 |

多模特的商品数固定为一个；多商品的模特数固定为一个。换装中的多张参考图共同描述本次服装，不能按图片数解释成多商品任务。

本次包含配置、素材选择、AI 模特参考配置、生成中及结果状态、完整历史、再次生成和结果归档。真实服装识别、真实人物生成、试穿生成、云端存储及结果文件下载属于后续服务接入。

## 2. 入口与页面布局

| 入口 / 区域 | 交互 |
| --- | --- |
| 侧栏与顶部功能导航 | 点击「AI 换装」进入页面，默认换装页签 |
| 商品详情「用此商品创作 → AI 换装」 | 带入当前商品稳定 ID、名称和参考图，进入换装配置 |
| 左侧配置 | 四个页签分别保存页面内草稿；切换时恢复本页签输入 |
| 右侧工作区 | 未生成时展示说明；生成中展示处理中状态；完成后只展示本次结果 |
| 历史记录 | 顶部按钮打开右侧抽屉，按完成时间倒序查看，不占据当前任务工作区 |
| 新建任务 | 清空当前页签的输入、结果及商品关联，恢复本页签默认值；不删除历史 |

生成中禁止修改输入、重复提交和切换页签；完成后配置只读。换一个配置继续创作时，使用新建任务或从历史复制。窄屏采用上下布局，页面内长表单可滚动。

## 3. 通用素材与模特规则

### 3.1 图片上传与选择

- 支持 JPG、JPEG、PNG、WEBP，单张不超过 10 MB；校验扩展名、MIME 类型和图片可读性。
- 支持本地文件、拖拽与素材库；商品图按对应模式提供商品库入口。
- 多选入口可连续添加，达到数量上限后不再添加；单选入口选择后关闭弹窗，再次选择替换当前项。单选拖入多张时只取首张。
- 已添加图片可预览和移除；移除只改变本次任务输入，不删除源素材。
- 图片读取失败或格式不符时提示原因，不清除已有可用输入。原型保存最长边不超过 1200px 的 JPEG，不能按原图无损存储验收。

### 3.2 单模特来源

换装和多商品共用单模特配置，来源为本地上传、素材库、AI 生成，默认本地上传。切换来源清除旧模特图，避免上一来源误参与生成。

| AI 模特字段 | 选项 | 默认 |
| --- | --- | --- |
| 性别 | 女性、男性 | 女性 |
| 年龄 | 青年、中年、老年 | 青年 |
| 外貌风格 | 东亚、欧美、南亚、非洲、拉美 | 东亚 |
| 体型 | 标准、纤瘦、健美、丰满 | 标准 |
| 补充细节 | 选填，最多 500 字符，可描述发型、妆容等 | 空 |

AI 模式必须点击「生成模特参考图」，获得参考图后才能提交。修改以上参数使当前单模特参考图失效，需重新生成。当前只载入固定人物演示图，不能按参数真实控制人物外貌。

### 3.3 背景、要求与输出设置

背景参考各页签均选填，默认折叠，可上传或从素材库单选一张。不填时保留人物原背景；多模特分别保留各自原背景。

补充要求选填，最多 2000 字符。模型为即梦 Seedream 4.5 / 4.0，默认 4.5；清晰度为 2K / 1K / 4K，默认 2K；比例为 3:4、1:1、4:5、9:16、Auto，默认 3:4。以上为演示配置，不表示已调用对应服务。

## 4. 换装

### 4.1 输入与识别

服装参考图放首位，必填 1–6 张，统一上传，不要求先选择套装、多件或上衣、下装。用户随后选择一个模特。

每张服装图可选择「AI 自动识别、上衣、下装、连体装、外套、整套穿搭、其他」，默认 AI 自动识别。该字段用于表达识别意图或纠正类型；当前原型没有真实识别响应，不生成伪造分类。

Pose 姿势参考选填一张，默认折叠；不填时保留模特原姿势。背景与要求按通用规则处理。

### 4.2 主流程与输出

1. 添加服装参考图，选择或生成一个模特参考图。
2. 可选姿势与背景，填写补充要求，设置模型、清晰度、比例和张数。
3. 张数可选 1、2、3、4，默认 1；服装与模特就绪后可直接生成，不要求先确认提示词。
4. 生成中禁用配置和重复提交；完成后右侧显示本次结果、参数摘要与生成要求，支持大图预览。
5. 保存全部输入、设置、生成要求和结果到历史，并按商品关联规则归档。

从商品库选择会替换服装参考并关联稳定 productId；改名不改变关联。追加参考图保留关联，清空全部服装解除关联。单纯图片选择不推断商品归属。

## 5. 改姿势

### 5.1 人物与姿势选择

上传或从素材库选择一张人物图，保留人物身份与原有服装，不要求服装图或 AI 模特配置。

| 模式 | 交互 |
| --- | --- |
| 预设 | 默认模式，按全身、上半身、下半身筛选，每类 15 项；跨分类合计选择 1–8 个 |
| 自定义 | 上传、拖拽或从素材库连续添加 1–8 张姿势参考图，可预览和移除 |

预设姿势为正面站立、背面站立、侧身站立、双手叉腰、回头侧望、自然垂手、单手叉腰、双手背后、向前走动、侧身行走、抬手回望、轻盈跑步、单腿微屈、自然坐姿、双手插兜。

点击已选预设取消选择；切换身体分类不清除选择。预设与自定义分别保留草稿，只有当前模式参与生成。预设卡片为矢量示意，不是生成效果。

### 5.2 输出

至少一张人物图和一个当前模式姿势才可提交。每姿势生成一张，不显示额外张数下拉。结果标注姿势名，历史保存预设 ID、名称、身体分类和示意图，以及自定义图、人物图、设置与结果。

当前改姿势不单独选择库商品，不根据人物图猜测商品 ID；结果进入 AI生成，来源为 AI 改姿势。

## 6. 多模特：一个商品，多个模特

### 6.1 商品单选

商品选择放首位，必填一个库商品或一张商品图。商品库只取该商品封面；选择后关闭弹窗，再次选择替换当前商品。纯图片不推断商品关联，替换成本地/素材库图片或移除时清除旧 productId。

### 6.2 模特多选

预设、自定义和 AI 生成三种入口统一加入已选模特列表，可混合添加，合计 1–8 个。切换添加入口不清除已有模特。

| 入口 | 交互 |
| --- | --- |
| 预设 | 选择示例人物卡片，再次点击取消；保存 presetId 和独立 modelId |
| 自定义 | 多张本地上传、拖拽或素材库连续选择；可在统一已选列表预览、移除 |
| AI 生成 | 性别、年龄、外貌风格、体型及细节与单模特相同；每次点击生成并添加一个模特，保存独立 modelId 和参数快照 |

多模特 AI 表单修改只影响下一次添加，不修改已经加入列表的模特。当前使用按性别选取的固定人物图演示，不真实响应其他外貌参数。

### 6.3 输出与关联

商品和至少一个模特就绪后可提交，每模特一张，不显示张数下拉。保留各自身份和原姿势，背景不填则各自保留原背景。

结果标注模特名，逐张保存 modelId、modelName、taskId 和 assetId。库商品的所有结果关联到同一个 productId；纯图片结果只进入 AI生成。来源为 AI 多模特试穿。

旧版多张商品参考的历史复制到新任务时，只保留首张商品图，避免违反当前单选规则。

## 7. 多商品：多个商品，一个模特

### 7.1 模特单选与商品多选

先选择一个模特，支持本地、素材库及 AI 生成，再添加 1–5 个商品条目，每项一张图。

每张图代表一个独立商品，同一模特逐项试穿，不把多张商品图合为一套穿搭。支持本地上传、拖拽、素材库及商品库连续选择；商品库每次只取选中商品的封面图，并在该条目保存稳定 productId 和标题快照。

库商品和手动素材可混合添加，可预览、移除。每项独立显示商品关联，不共享任务级 productId。

### 7.2 输出与关联

至少一个模特和一个商品才可提交。每个商品生成一张，不显示张数下拉，保留同一人物身份和原姿势。

结果标注商品名；每张记录独立 assetId、taskId、输入图名和条目对应的可选 productId。全部结果进入 AI生成，库商品结果分别进入各自商品详情；手动图片只进入 AI生成。来源为 AI 多商品试穿。

## 8. 任务状态、历史与再次生成

| 状态 / 操作 | 行为 |
| --- | --- |
| 输入不足 | 生成按钮不可用，提示缺失的必填素材 |
| 可生成 | 当前模式必填素材齐全，按设置或多选项数量计算输出 |
| 生成中 | 禁止重复提交、修改输入、新建和切换页签 |
| 完成 | 参数只读，展示当前任务结果和生成要求；可预览、看历史或新建 |
| 存储失败 | 提示本机存储失败，释放空间后可重试，不宣称归档成功 |
| 历史详情 | 查看完整输入、设置、模特参数、关联信息、生成要求和全部结果 |
| 以此任务再次生成 | 复制完整快照，产生新 taskId，清空结果，恢复对应页签和设置，不覆盖原历史 |
| 新建任务 | 清空当前页签输入、商品关联和结果，恢复默认；其他页签草稿保留 |

历史共用一个抽屉，列表显示任务类型、名称、结果数和完成时间。草稿仅存在于当前页面状态中，刷新后不保证恢复；已完成历史使用本机 IndexedDB 保存。

## 9. 结果归档与数据契约

| 数据 | 规则 |
| --- | --- |
| taskId | 每次新建或历史复制产生独立 ID |
| assetId | 每张成功结果一个唯一 ID |
| productId | 只来自显式商品库选择或商品详情传入；不使用名称或相似图片猜测 |
| 多模特关联 | 同一商品的所有模特结果共享该商品 ID |
| 多商品关联 | 按 goods 条目分别归档，不串商品 |
| 中间 AI 模特图 | 保存在任务快照，不作为最终试穿结果单独归档 |
| 删除关系 | 沿用共享资产库删除规则；历史快照不因删除资产记录而被清除 |

当前结果保存到浏览器共享本地存储，历史保存到独立 IndexedDB。原型先保存历史再写结果资产，两步不是原子事务；结果写入失败时可能留下历史，应在正式开发中由服务端保证一致性，避免重试重复归档。

## 10. 验收标准

1. 四个页签输入互相隔离，切换恢复页面内草稿；生成中不可切换。
2. 换装服装入口在首位，没有套装/多件切换；不强制上下装分开上传。
3. 单模特三种来源可用；AI 参数修改后，旧参考图失效；重新生成后恢复提交资格。
4. 改姿势跨分类最多 8 个，切换分类保留选择；自定义最多 8 张；仅当前模式计算结果。
5. 多模特商品严格单选，再选替换；模特可混合多选，上限 8 个，输出数等于模特数。
6. 多商品商品可多选，上限 5 个；模特严格单选，输出数等于商品数。
7. 背景和补充要求留空也能生成；无背景时保留各自原背景。
8. 完成后配置只读；新建清空当前输入和商品关联；历史复制产生新 ID，不改变旧任务。
9. 多商品结果按各自 productId 关联；纯素材无商品关联，只进入 AI生成。
10. 错误格式、超量、不可读取图片及存储失败有提示；不误报真实 AI 识别或生成成功。

## 11. 原型与正式服务的区别

当前自动识别仅保存意图或人工纠正值，没有分类服务。AI 模特为固定示例图，换装与改姿势结果沿用人物参考图，明确标注演示占位，不是真实生成效果。预设人物照片依赖外部图片地址，加载受网络影响。

正式接入时需另行完成服装理解、生成任务服务、真实模型调用、异步状态与重试、结果文件存储及预览、服务端归档一致性和权限隔离。模型名称、清晰度与比例当前只是原型选项，实际能力以接入服务验证为准。
